# Wiki 定位演练核验记录

2026-10-14；业务代码基线 `8f55892`。本轮没有修改接口实现，候选改进保持[提案状态](Interface-improvement-plan.md)。

## 读文档与读代码分开记录

1. 文档阶段：Home → 相关使用页 → 原架构表及 CONTRIBUTING，形成第一版候选计划；没有全仓源码搜索。
2. 补路由：将文档已提到的声明、实现、调用边界和检查命令登记到 routes.json，按 10 类任务组织。
3. 位置核对：工具只读路由中指明的源码文件，要求 needle 恰好命中一次；它确实读取源码，但不替人猜文件、不做全仓搜索。行号来自当前内容。
4. 语义抽查：定点读取服务的 onsiteRecords、账本的 decideChangeRequest、外部源端口，补充了“先生效标签筛选，再审阅门槛”的实际顺序。其余摘要不是逐行全量调用追踪。

“完全不读源码即可写第一版 plan”与“完全不核对源码即可实施”是不同标准。本轮支持前者，不支持后者。

## 如何复核

```sh
python tools/wiki_route.py --build
python tools/wiki_route.py --check
python -m unittest discover -s tools -p test_wiki_route.py
python tools/wiki_route.py "外部源端口"
python tools/wiki_route.py "模型贡献"
python tools/wiki_route.py "不存在的任务XYZ"
```

位置/锚点核验只证明导航结构。路由测试另外检验真实自然语言问题能否命中预期层级，以及移动声明、缺失/重复声明、错误锚点、未知问题的表现；它不证明新接口已实现。

本轮作者已熟悉项目，未做独立陌生执行者盲测；因此不能声称“任何代理一定主动先用 Wiki”。AGENTS 与首页提供短入口，价值来自一次查询即可拿到位置、边界和检查，而不是强制全站阅读。
